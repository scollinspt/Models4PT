Papers and prior writings that this case study draws on (the "Synthesis"
referred to in the parent README), plus the draft causal models in whatever
form they currently exist.

Contents:
- `Collins - 2018 - Synthesis Causal Models, Causal Knowledge.pdf`,
  `Collins_KBP_ProjectExample.pdf`, `PopKnowledgePatientReasoning.pdf` — prior
  writings.
- `Realist Theory of Science.pdf` — Bhaskar's book, source for the critical
  realism domains (Real/Actual/Empirical) being explored for this model; see
  `../notes.md`.
- `PCM5 - Quadrants.png`, `PCM5 Algorithm.png`,
  `Quadrant-Pathway-ThoughtProcess_1.5.png`, `Quadrant_Thought_Process_1.0.png`,
  `Quadrants_1.pdf`, `HF-CPG-Algorithm.png` — the clinical reasoning system
  taught in the author's cardiopulmonary PT course (PCM 5): the Attain/Sustain
  x Reversible/disease-specific quadrant framework and the HF-CPG decision
  algorithm built on it. Connects directly to the model — see `../notes.md`
  session log for how.
- `model1.png`, `model2a.png`, `Model3.png`, `Model4.png` — pictures of
  successive draft models. The most complete is model 4D, pictured in
  `Model4.png`; the DAGitty code for it is in `../model/Model4b.docx`.
- A short `provenance.md` noting where each artifact came from and its date/
  version, so later refinement in `../model/` can be traced back to source
  (not yet added).

Note on DAGitty: DAGitty is built for constructing population-level models
and planning studies, not for patient-level instantiation. Earlier attempts
to co-opt DAGitty for instantiation didn't work — that limitation is part of
why this project shifted from modifying DAGitty to building Models4PT/CIE.
So the DAGitty version of model 4D is a useful starting skeleton (possible
causal connections) but does not contain the representation Models4PT/CIE
actually needs — that gap is exactly what this case study should surface.

Treat this folder as input material — refine the model in `../model/`,
don't edit these files in place.
